# KodoStars v1.0 — дизайн доработки до продакшен-уровня

Дата: 2026-09-15. Автономный режим: решения приняты без промежуточных вопросов,
все спорные места зафиксированы ниже с обоснованием.

## Цель

Довести бот до состояния «лучший реферальный бот на Stars»: корректная экономика без гонок,
полноценная админ-панель внутри Telegram, миграции БД, фоновые рассылки, аудит действий,
полировка пользовательского UX, тесты на всю доменную логику.

## Найденные дефекты текущей версии (исправляются)

1. `app/services/daily.py`: `datetime` не импортирован → `NameError` при получении ежедневки.
2. `get_balance` суммирует весь леджер при каждом вызове; `append_entry` делает read-then-write
   (гонка при параллельных обновлениях, неверный `balance_after`).
3. Заявка на вывод не резервирует средства: пользователь видит «полный» баланс при открытой заявке.
4. `fulfill_boost_payment` при повторной доставке `successful_payment` бросает `ValueError`.
5. Задания типа `subscribe` невозможно выполнить: проверка подписки не вызывается.
6. Рефералка привязывается к уже существующему пользователю (`referred_by_id is None`),
   а не только при первом старте → накрутка на старых аккаунтах.
7. Рассылка выполняется синхронно внутри хендлера, без лимитов Telegram, прогресса и отмены.
8. Админ и пользователь не получают уведомлений по заявкам на вывод.
9. Нет глобального обработчика ошибок; `edit_text` с тем же текстом падает с `TelegramBadRequest`.
10. `bot.get_me()` вызывается на каждый рендер главного экрана.
11. Нет миграций — `create_all` не добавляет колонки в существующую БД.
12. `tests/test_root_main.py` использует `cwd="/tmp"` — не работает на Windows.
13. In-memory кэши `_links` в OP-адаптерах растут без ограничений.

## Ключевые архитектурные решения

### Баланс
Денормализованная колонка `users.balance`, изменяемая одним атомарным
`UPDATE users SET balance = balance + :delta WHERE id = :id [AND balance + :delta >= 0] RETURNING balance`.
Леджер остаётся полным журналом (`balance_after` берётся из RETURNING). Миграция бэкфиллит
баланс суммой леджера. Админ-инструмент «Сверка» сравнивает `sum(ledger)` и `users.balance`.

### Вывод (hold-семантика)
`apply` → списание `WITHDRAW_HOLD` (баланс уменьшается сразу, видно «в холде»).
`reject`/`cancel` → возврат `WITHDRAW_REFUND`. `approve_manual` → статус. `confirm_sent` → статус
`sent` без движения по леджеру (средства уже списаны). Пользователь может отменить `pending`.
Админы получают карточку заявки с кнопками сразу при создании; пользователь получает
уведомления о каждом изменении статуса. Опционально `WITHDRAW_MIN_REFERRALS` (активированных L1).

### Платежи и возвраты
Таблица `payments` (charge_id уникален, сумма XTR, статус paid/refunded). Повторный
`successful_payment` с тем же charge_id — идемпотентен. Админ может сделать `refundStarPayment`:
для `stars_pack` списывает начисленные Stars (допускается уход в минус — админ видит
предупреждение), для множителя — мгновенно истекает буст. Команды `/paysupport`, `/terms`.

### Доступ и роли
Владельцы — `ADMIN_IDS` из env (нельзя удалить из бота). Админы — таблица `admins`, управляются
владельцами из панели. Единый `IsAdmin`-фильтр на админ-роутерах вместо проверок в каждом хендлере.
Все админ-действия пишутся в `admin_actions` (аудит).

### Настройки в рантайме
Таблица `app_settings` (key → JSON). Белый список переопределяемых ключей экономики и
операционных флагов (`maintenance_mode`, `withdraw_enabled`, `manual_op_channels`,
`support_contact`, …). Middleware подменяет `data["settings"]` на эффективную копию
(`Settings.model_copy(update=overrides)`), сервисы не меняются. Кэш в памяти,
инвалидируется при изменении из панели.

### Рассылки
Таблица `broadcasts` + фоновый воркер `asyncio.Task`. `copy_message` (любой тип контента,
форматирование сохраняется) + опциональная URL-кнопка. Аудитория: все / активные 7 дней /
только с активированной рефкой. Rate-limit ~20 сообщений/с, обработка `TelegramRetryAfter`,
`TelegramForbiddenError` → пометка `blocked_bot_at`. Прогресс-карточка у админа, кнопка «Стоп»,
тестовая отправка себе перед запуском.

### Миграции
Alembic, `app/migrations`. `0001_baseline` — точная схема старой версии; `0002_v1` — все новые
таблицы/колонки (только ADD, совместимо с SQLite). Программный запуск на старте: если есть
`users`, но нет `alembic_version` → `stamp 0001`, затем `upgrade head`. Тесты по-прежнему используют
`create_all`; отдельный тест проверяет, что `upgrade head` на пустой БД даёт тот же набор таблиц
и колонок, что и `create_all`.

### Надёжность
Глобальный `errors`-хендлер (лог + мягкий ответ + алерт владельцам), `safe_edit`
(игнорирует «message is not modified»), кэш `bot.username`, throttle-middleware
(per-user, 0.4 с на callback), трекинг блокировки бота через `my_chat_member`,
structlog-контекст `user_id/update_id`, общий `aiohttp.ClientSession` для OP-адаптеров,
ограниченные кэши ссылок в адаптерах, Dockerfile + docker-compose (SQLite / Postgres).

## Функциональность пользователя

Главное меню: Профиль · Рефералы · Ежедневка · Задания · Бусты · Топ · Вывод · Промокод ·
Помощь (+ Админка). Команды: `/start`, `/menu`, `/profile`, `/help`, `/paysupport`, `/terms`,
`/admin`. Профиль: баланс, холд, прогресс уровня (полоска), серия, рефералы, история операций
(постранично). Рефералы: кнопка «Поделиться» (`t.me/share/url`), уведомление рефереру о новом
и об активированном реферале. Топ: по рефералам и по заработку за 7 дней (никнеймы маскируются).
Вывод: быстрые суммы + «Своя сумма», список заявок, отмена `pending`. Промокоды: ввод кода.
Задания `subscribe` проверяются через `getChatMember`, `custom` с `url` — «перейти и получить».

## Админ-панель

Разделы: Статистика · Пользователи · Выводы · Рассылка · Задания · Бусты · Промокоды ·
Платежи · Настройки · ОП-провайдеры · Каналы ОП · Админы · Журнал · Экспорт/Импорт · Антифрод.

- Статистика: пользователи (всего/сегодня/7д/30д, заблокировали бота, баны), DAU/WAU,
  воронка рефералов, экономика по видам начислений, холд, выведено, XTR-выручка,
  баланс Stars бота (`getMyStarBalance`), очередь выводов, последняя рассылка.
- Пользователь: поиск по ID/@username, карточка (баланс, холд, уровень, рефы, активность,
  бан, платежи, заявки), действия: ±баланс с причиной, бан/разбан, написать сообщение,
  леджер, рефералы, фрод-события.
- Выводы: фильтры pending/approved/история, пагинация, карточка с контекстом пользователя,
  отклонение с причиной, согласование, подтверждение отправки.
- Задания/Бусты/Промокоды: создание мастером (FSM), вкл/выкл, изменение награды/цены, удаление.
- Настройки: список ключей с текущими значениями, изменение, сброс к env-значению.
- Каналы ОП (manual): добавить/удалить `@channel` или `-100…`, проверка прав бота.
- Админы: список, добавить/удалить (только владельцы).
- Журнал: последние действия админов. Экспорт: CSV пользователей/выводов/леджера.
  Антифрод: последние события, подозрительные аккаунты (много рефов, низкая активация).

## Тесты

Доменные сервисы (леджер атомарный, холд, платежи идемпотентность/рефанд, промокоды, ежедневка,
задания, рефералы первый старт, настройки, доступ, аудит, рассылка с фейковым ботом, статистика,
лидерборд, экспорт), middleware (throttle, settings), миграции (fresh == create_all; legacy stamp).

## Вне рамок (осознанно)

Redis-FSM, web-панель, i18n, автоматическая выплата подарками (`sendGift` даёт не ту сумму),
напоминания о ежедневке (следующая итерация), конкурсы.
