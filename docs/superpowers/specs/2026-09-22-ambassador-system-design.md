# KodoStars — система амбассадоров

Дата: 2026-09-22. Согласовано с Daniel (варианты: гибридные дневные промо, полный кастом L1/L2, двухшаговый автопост, несколько площадок, подход A — `AmbassadorSlot`).

## Цель

Дать владельцам каналов/чатов/ботов подавать заявку на партнёрство. После одобрения админ выдаёт персональные реф-условия и шаблон дневных промокодов; для каналов/чатов — опциональная публикация промокода (наш бот должен быть админом).

## Решения

### 1. Сущность `AmbassadorSlot` (подход A)

Одна заявка = один слот (площадка). У пользователя может быть **несколько** слотов с разными условиями.

**Таблица `ambassador_slots`**

| Поле | Назначение |
|---|---|
| `user_id` | Владелец |
| `kind` | `channel` \| `chat` \| `bot` |
| `title` | Отображаемое название |
| `invite_link` | Ссылка, указанная при подаче |
| `chat_id` | Telegram chat id (nullable; нужен для автопоста channel/chat) |
| `status` | `pending` → `approved` \| `rejected` \| `revoked` |
| `l1_bonus`, `l1_percent`, `l2_bonus`, `l2_percent` | Полный кастом реф-условий (nullable до апрува) |
| `promo_reward`, `promo_max_uses` | Шаблон дневного промокода |
| `promo_auto_post` | Автопост после выдачи кода (только channel/chat) |
| `reviewed_by`, `reviewed_at`, `reject_reason` | Аудит решения |
| timestamps | `created_at`, `updated_at` |

Индексы: `(user_id, status)`, уникальность активной заявки на ту же площадку — `(user_id, invite_link)` среди `pending`/`approved` (или нормализованный link + `chat_id` когда известен).

Миграция: **`0008_ambassador_slots`**.

### 2. Реф-условия

- При начислении бонуса активации и share % для referrer’а: среди его **`approved`** слотов берётся **максимум по каждому полю** отдельно (`l1_bonus`, `l1_percent`, `l2_bonus`, `l2_percent`).
- Если approved-слотов нет — глобальные `Settings` как сейчас.
- Поля не суммируются (анти-абуз стакингом площадок).
- `revoked` / `rejected` не участвуют.
- L1/L2 по-прежнему идут через существующие `ReferralEdge` + `activate_if_ready` / `share_earning`; меняются только суммы/проценты источника.

Точки интеграции: `app/services/referrals.py` — резолвер `effective_referral_terms(session, referrer_id) -> Terms`.

### 3. Дневные промокоды (гибрид)

- Амбассадор на карточке approved-слота жмёт **«Получить промокод»** (не чаще 1 раза за календарные сутки **UTC**).
- Система создаёт обычный `PromoCode` с:
  - `ambassador_slot_id` (новая nullable FK),
  - `reward` / `max_uses` из шаблона слота,
  - `expires_at` = конец текущих суток UTC,
  - код вида `AMB` + короткий уникальный суффикс.
- Повторное нажатие в тот же день возвращает **уже выданный** код (не создаёт второй).
- Redeem без изменений (`services/promo.py`), лимит один redeem на user на код.

**`promo_codes`:** колонка `ambassador_slot_id` (FK, nullable) + уникальный partial/composite constraint: один код на `(slot_id, day_utc)` для слотовых кодов.

### 4. Автопост (двухшаговый)

1. Админ может **одобрить** слот и задать реф/промо-условия без автопоста.
2. Флаг `promo_auto_post` включается **только** если `kind ∈ {channel, chat}` и `getChatMember(bot)` ∈ `{administrator, creator}` в `chat_id`.
3. Тип `bot`: автопост недоступен (только ссылка + условия + ручная выдача кода).
4. После «Получить промокод», если `promo_auto_post`: бот делает `send_message(chat_id, …)` с кодом и кратким текстом. Ошибка прав → сброс флага + уведомление амбассадору/админу.
5. Ручная кнопка «Опубликовать сегодня» — если код уже выдан, а пост не ушёл / флаг выключен, но права есть.

Резолв `chat_id`: при апруве/проверке прав админ может указать numeric id, либо бот пытается резолвить из invite (если публичный `@username`); для invite-ссылок `t.me/+…` админ вводит `chat_id` вручную после добавления бота.

### 5. Пользовательский UX

- Главное меню: кнопка **«Амбассадор»**.
- Список слотов + «Подать заявку».
- FSM заявки: kind → invite_link → title → confirm → `pending`.
- Карточка approved: условия, сегодняшний промокод / кнопка выдачи, статус автопоста.
- Rejected: причина + возможность подать новую заявку на другую/ту же площадку после отклонения (rejected не блокирует unique active).

### 6. Админ UX

- Корень админки: **«Амбассадоры»** (очередь pending + список approved), по аналогии с Выводами.
- Карточка pending: Approve (FSM: L1/L2 bonus/%, promo reward, promo max_uses) / Reject (причина).
- Карточка approved: правка условий, «Проверить права бота», toggle автопоста, Revoke.
- Уведомление админам о новой заявке (как у выводов — через `Notifier`, если уже есть паттерн pending alerts).

### 7. Границы v1

**В scope:** слоты, апрув/reject/revoke, кастом L1/L2 (max), дневные промо, автопост channel/chat, миграция, UI, тесты.

**Вне scope:** отдельная аналитика трафика амбассадора; автогенерация без кнопки; proof-of-ownership через код в описании; отдельные выплаты сверх реф-системы; автопост в «бот»-площадки.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Невалидная ссылка | Отказ на вводе |
| Дубликат pending/approved той же ссылки у юзера | «Уже есть заявка» |
| Промо без approved | Алерт |
| Повтор выдачи в тот же UTC-день | Показать существующий код |
| Автопост без admin-прав | Не включить / сбросить флаг + сообщение |
| Revoke | Слот не даёт реф-оверрайды; уже созданные промо живут до `expires_at` |

## Тесты

- Approve → `effective_referral_terms` возвращает кастом; `activate_if_ready` / `share_earning` используют его.
- Несколько approved-слотов → max по полям.
- Дневной промо: один на сутки; redeem как обычный promo.
- Автопост: мок send в `chat_id`; отказ без admin.
- Reject / revoke снимают влияние на реф-условия.

## Статусы слота (машина)

```
pending ──approve──► approved ──revoke──► revoked
   │
   └──reject──► rejected
```

Из `rejected` / `revoked` новая заявка = новый ряд (история сохраняется).
